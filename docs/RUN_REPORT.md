## 6. 完整剧情确实在卡里 —— 以及这意味着什么

`剧情主线（逐章）` 条目 25,483 字，**覆盖第 1–156 章全部章节**，每章一行走向。
该条目是**触发**条目（键：剧情 / 主线 / 前情 / 结局 / 回忆…）。

**必须说清楚的一点：这是剧透面，不是剧透防护。**
完整剧情与模型可见的核心规则在**同一张卡**里，没有任何机制阻止模型读到它。
当前唯一的约束是核心规则第 7 条的文字要求：

> 标注章节晚于当前起始点的内容尚未发生，NPC 不得据此行动、不得提前知道。

**这是提示词层面的行为约束，不是访问控制。** 触发命中、用户直接追问剧情、
或模型自行判定该内容相关时，后续剧情都可能进入上下文。因此：

| 档位 | 机制 | 保证 |
|---|---|---|
| 默认单卡 | 核心规则的**时间纪律** | **尽力而为**，可能漏 |
| `worldbook_start_beginning.json` | 只丢剧情条目，人物与地点条目仍聚合全书事实 | **不严格** —— 只是去掉最明显的那个 |
| `card_start_chapter_N.json` | 起点之后的事实**不写入任何条目正文** | **结构性**，内容不在文件里 |

**要硬保证就必须换文件，不能只靠换提示词。** 那些文件**没进本仓库**，需本地重跑导出。

## 7. 忠实度：怎么保证「不与原文剧情和人物行为不符」

机制有四种，逐层可验证：

1. **引文必须逐字存在。** 抽取只产出引文，行号由 `locate_quote` 在原文里检索后反推。
   本次 5,746 条引文 100% 命中。
2. **没有证据的内容不进 canon。** 声称 `canon_fact` 但引文定位失败的条目不写进条目正文。
3. **引文存在还要问「支不支持」。** `n2t verify` 能判断引文是否支持那条主张 ——
   **本次没有跑**（需要可用的 API 额度），清单里标注 `executed: false`。
4. **人工抽查。** 随机抽 10 条事实回原文对应行核对（见下），抽查通过。
5. **黄金集。** `examples/gold/` 在自创的八章微型小说上量精确率/召回率 ——
   但那测的是**管线**，不是本次这次运行的模型质量。

### 这套机制证明了什么，没证明什么

| 已证明 | 未证明 |
|---|---|
| 引文**逐字存在于原文** | 引文被**正确解读** |
| 行号是**程序算出**的，非模型自报 | 事实**归属给正确的人物** |
| 定位失败的条目被挡在 canon 之外 | 没漏掉否定词、没有把传闻当事实 |
| —— | 复杂事实的**全部要件**都被覆盖 |
| —— | 抽取的**遗漏率**（低到多少不知道） |

第 2 项「待人工复核 0 条」的真实含义是**引文定位失败数为 0**，
**不是**「抽取结果已逐条人工审校」。本次运行**没有跑语义支持校验**，
所以在「引文支不支持主张」这一层上**没有任何度量**。下表只是**来源定位**指标。

## 8. 已知限制

1. **Tavo 只验证到「导入成功」。** 触发命中、常驻注入、剧透行为、token 占用**均未验证**（见第 1 节表）。
   官方文档无字段级说明，本项目不做任何 Tavo 专属假设。
2. **默认档的剧透防护是提示词层面的，不是访问控制。** 单卡含全书剧情；
   硬保证需用 `--start-chapter N`（见第 6 节）。
3. **本次没有跑语义支持校验。** 100% 引文定位率只证明引文在原文里存在（见第 7 节）。
   `n2t verify` 已实现并有测试，但没有可用的 API 额度来对真实语料跑一遍。
4. **`insertion_order` 方向语义未定论**（规范与 ST 文档描述相反），条目顺序先用 ST 模板默认值。
5. **事件没有绝对时间**：`occurred_at` 恒为 `null`，原文的「次日」只作 `relative_time` 原样记录。
6. **知识边界大量是「不知道」，这是刻意的。** 3,806 条知识记录里只有 1,728 条是已确立的
   `knows`（判据是「事实的主语就是它自己」），**2,078 条是候补** —— 事件参与者记为
   `candidate=True`、状态 `unknown`、`acquired_at_chapter` 留空。**在场不等于知晓。**
   角色通过信件、报告、传闻、他人转述或自行推断获得的知识，当前模型表达不了。
7. **条目正文只保留 canon 事实，但抽取遗漏未被度量**：出场多而事实少的实体
   （如只抽到 1 条事实的重要地点）多为**抽取遗漏**，不是原著里真的没写。
8. **188 条合并候选待人工复核**：名字相似但证据不足的实体对**没有**被自动合并
   （例如「西泽尔 ✕ 红龙」—— 抽取器在 31 个分块里把「红龙」记为西泽尔的别名，
   但「红龙」同时是机甲名，类别冲突，故拦下）。
9. **260 条冲突只报告未解决**：同一主语同一谓词出现多个取值，需人工判断是随时间变化还是原文矛盾。
10. **事实来自自动抽取，仅做了抽样核对**，未逐条人工审校。

```bash
.venv/bin/n2t verify  --run-id <run_id>         # ④ 语义校验（本次未跑：需要 API 额度）
.venv/bin/n2t timeline --run-id <run_id>        # ⑤ 839 事件 / 178 规划条目
.venv/bin/n2t export  --run-id <run_id> \
    --start-chapter 1                           # ⑥ 180 条目 + 严格档 8 条目
```

**注意执行顺序**：`verify` 必须排在 `timeline` 与 `export` **之前** ——
`timeline` 会读取 `verification/semantic.json` 并把判定为有问题的那些事实
排除在条目正文之外。没跑过 `verify` 也没关系，`timeline` 会在报告里写「未执行」。

`verify` 需要可用的抽取引擎。用 `file` 引擎且没有预生成校验响应时，它会**直接报错中止**
（而不是把所有事实判为有问题、把世界书清空）。
