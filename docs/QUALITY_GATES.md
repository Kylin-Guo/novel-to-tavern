# 质量门禁与测试用例

## A. 来源完整性

- [ ] 每个 canon 事实至少有一个有效 source ref。
- [ ] source ref 指向存在的文件、章节和范围。
- [ ] 没有把模型生成补全标为 canon。
- [ ] 章节覆盖率可计算；未处理章节在报告中列出。
- [ ] 提取原始响应、中间 schema 和最终结果可互相追溯。

## A2. 语义支持（`n2t verify`）

引文能定位 **不等于** 引文支持那条主张。这一节与 A 是两层，都要过。

- [ ] 高重要性事实（身份 / 生死 / 秘密 / 关系 / 能力 / 立场）已做语义支持校验。
- [ ] 判定为 `contradicted` / `insufficient_evidence` 的事实**不进**条目正文。
- [ ] `partially_supported` **不排除**，但计数必须出现在报告里 ——
      本卡定位是「世界模拟器资料」而非严格考据，见 §H。
- [ ] 校验一条都没调通时**整体中止**，不产出「全部有问题」的报告
      （那会把世界书静默清空）。
- [ ] 未执行时，导出清单里如实写 `executed: false`，不写成 0 分、也不写成通过。

## B. 角色和实体一致性

- [ ] 同名不同人不能被误合并。
- [ ] 同一人物的别名/称号在有依据时能合并。
- [ ] 不确定实体对进入 review queue。
- [ ] 人物重要性不能用 JSON 文件大小代替。
- [ ] 不因 keep_count 默默删除配角；如裁剪必须显式记录。
- [ ] 角色性格结论能关联到行为例证，而不是全凭标签。

## C. 时间线和知识边界

准备一个玩具小说 fixture：第 2 章发生秘密事件，第 8 章才揭露真相；只有两个指定人物在第 2 章知情。

- [ ] 从第 3 章开始时，不应把第 8 章的真相作为世界已确认信息注入。
- [ ] 未知情 NPC 不应在其无合法获知来源时说出秘密。
- [ ] 事件发生时间和消息揭露时间分开。
- [ ] 分支模式不强制复现后续原著事件。
- [ ] 相互冲突的来源进入 contradiction report。

## D. 世界书触发质量

- [ ] 世界核心规则不依赖普通关键词才能加载。
- [ ] 角色详情可以由姓名、有效别名或称号触发。
- [ ] 常用词不会让大量无关条目同时触发。
- [ ] secondary keys/逻辑按目标格式真实支持的字段生成。
- [ ] 触发词、递归、插入位置、优先级均由 serializer 验证。
- [ ] 常驻内容长度有估算和预算警告。

## E. JSON 与导入格式

- [ ] 输出严格有效 JSON，无注释、尾逗号或未转义字符串。
- [ ] Character Card V2 标识、data 包装、character_book 位置符合已确认的目标规范。
- [ ] 内嵌/独立 worldbook 的条目数和关键字段一致。
- [ ] uid 唯一；position/insertion order/keys 等类型正确。
- [ ] 无不认识的“猜测字段”；扩展字段有依据。
- [ ] 生成后能列出条目数、有效 keys 数和验证警告。
- [ ] 最终 Tavo 实测的结果与自动验证结果分开记录。
      → 见 `README.md`「验证等级」表：④⑤ 已验证，⑥–⑩ 未验证，两者不得混写。
- [ ] 剧透防护的描述与实现强度一致：默认单卡是**提示词层面**的尽力而为，
      只有导出时过滤的世界书才是结构性保证。

## F. API 和数据安全

- [ ] `.env` 不入库；日志不打印 API key。
- [ ] 默认测试不触发真实 API。
- [ ] 同样输入、提示词版本与模型配置可命中缓存。
- [ ] 修改源 chunk 或 prompt 版本会使相关缓存失效。
- [ ] 中断/重试不会重复追加错误条目或覆盖成功结果。
- [ ] 工作目录中的旧 run 不会自动删除。

## G. 输出报告最低内容

`audit.md` 至少报告：

- 原始文件、字节数、hash、识别章节数。
- 处理/未处理章节与 chunk 数。
- 实体总数、合并数、待审核数、未解决重复项数。
- 各 fact type 数量及缺失来源数。
- 世界书总条目、常驻条目、触发条目、每个条目的来源覆盖率。
- 时间线事件数、冲突数、疑似未来信息泄漏数。
- 导出 JSON 校验结果、Token 粗略预算（明确估算方法）、实际 API 用量（若可获取）。
- 未知项、警告、需人工检查的具体名单。

## H. 卡的口径：世界模拟器，不是考据

这一条决定了好几处「看起来不严」的地方为什么是有意为之：

- 卡的定位是**多角色世界模拟器**，资料用途，不是「逐字考据的原始文献」。
- 因此 `partially_supported` 的事实**照常进正文** —— 一句只支持了一半的复合事实，
  在世界模拟器里仍然是有用的设定；在考据场景里则必须排除。这是产品口径，不是疏漏。
- 因此**不设**「语义校验没跑完就不许导出」的硬门禁：那会让没有 API 额度的人
  彻底无法离线导出。取而代之的是**如实标注**（清单 `metrics.semantic_support.executed`、
  audit 报告写「未执行」）。
- 想换成严格口径的话，改动点是 `verify/schema.py` 的 `PROBLEM_VERDICTS`
  加上 `partially_supported`，以及给 export 加一个显式的 `--strict-fidelity` 开关。
  两处都有测试锁着当前行为，改的时候会失败提醒。
